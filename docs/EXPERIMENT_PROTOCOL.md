# 实验执行协议

## 阶段门槛

```text
环境探针
  → 数据身份与预处理验证
  → 静态检查和单元测试
  → 200 步冒烟
  → 正式训练
  → 完整 test、最终点云几何评估与最差相机诊断
  → 结果汇总
  → 持久存储回读
  → 完成登记与释放 GPU
```

后一个阶段只能在前一个阶段有明确证据后开始。

## 冒烟

- 使用真实数据和正式代码提交。
- 使用正式实验的学习率 horizon，避免把改变调度的运行误当等价冒烟。
- 检查 iteration 0 和最终轮 Val、有限 loss、反向传播、优化器、拓扑更新及 checkpoint。
- 每项新增功能至少有一个能证明其生效的日志字段或统计量。

## 正式训练

- 默认 150000 步；改变迭代数必须作为独立实验登记。
- 每次运行使用唯一 `run_id` 和新目录。
- 运行中持续记录 loss、指标、高斯数量、时间和显存信息。
- 不因为页面断开就重启；先检查会话、进程、日志和最新 checkpoint。
- 恢复训练记录父运行和 checkpoint 身份，并写入新目录。

## 实验组与功能开关

实验组只提供组合默认值。每个初始化、loss、尺度约束、增密、剪枝、监督和诊断功能都应有独立开关。推荐：

```text
--experiment-group original|A|B|C|D|E|custom
--feature-name auto|on|off
```

`auto` 继承 preset，`on/off` 显式覆盖。训练启动时输出最终矩阵，不能根据组名字推断实际功能。

## 完成标准

`completed.json` 只在以下条件全部满足后生成：

- 训练达到目标迭代。
- loss 全程有限，失败记录为空或已解释。
- 预期 checkpoint 和模型文件存在。
- 完整 test 的 PSNR/SSIM/MAE 及最差相机诊断存在。
- 最终模型相对已登记参考点云的双向距离、Chamfer、Precision/Recall/F-score 等几何指标存在。
- 几何报告记录单位、对齐方式、参考点云角色和输入哈希；初始化 LiDAR 只能解释为贴合初始几何，不能冒充独立真值。
- 结果表和实验总结存在。
- 文件已复制到持久存储并完成回读验收。



## 跨项目适配与失败降级

项目的相机、图像、模型和点云格式可以不同。优先在 adapter 或转换脚本中映射到本规范接口，源数据保持只读。几何评估器直接支持 PLY、NPY 和 NPZ；其他格式先由项目 adapter 导出为带单位和坐标系说明的 Nx3 点或 PLY。

每项最终评估都必须尝试执行。遇到缺少参考点云、渲染器不提供深度/法向、格式无法可靠转换或依赖不可用时，允许跳过相应指标。运行目录必须写 `evaluation_status.json`：

```json
{
  "visual_test": {"status": "completed", "reason": null},
  "geometry_test": {"status": "skipped", "reason": "reference point cloud is unavailable"}
}
```

验收脚本把有明确原因的跳过记为 warning；静默缺失仍视为错误。总结文档把未运行项列出并在对比表中保留 `null`。
