# 数据集与预处理契约

## 原始输入

每个项目在数据 manifest 中登记：

- RGB 图像路径、格式、尺寸和数量。
- mask 路径、有效值语义和覆盖率。
- 相机模型、内参、畸变状态、外参方向和相机中心计算方式。
- 点云来源、格式、字段、单位、包围盒、点数和哈希。
- 动态目标是否已清理、由哪个上游步骤生成。
- train/val/test 列表及内容哈希；固定 val 相机必须数量明确且无重复。

## 目录语义

```text
<scene>/
├── raw/                 # 只读原始输入
└── processed/<version>/ # 可重建派生数据
    ├── images/
    ├── masks/
    ├── cameras/
    ├── geometry/
    ├── supervision/
    ├── previews/
    └── manifests/
```

已有成熟数据目录不强制移动，但必须通过 manifest 映射到相同逻辑角色。

## 预处理验证

正式训练前至少验证：

1. RGB、mask、相机名称一一对应。
2. 外参方向、相机中心、场景尺度和点云单位正确。
3. 文本/二进制相机文件同时存在时内容一致，并记录训练实际读取版本。
4. LiDAR 到图像投影没有系统偏移，遮挡采用 z-buffer。
5. 深度说明是 camera-z 还是 ray distance；无效值有独立 valid mask。
6. 法向符号策略、置信度、未解析比例和有效覆盖率有记录。
7. 深度回投到三维后与源点云误差满足项目阈值。
8. 预处理脚本禁止无提示覆盖已有输出。
